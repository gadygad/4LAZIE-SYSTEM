Security Design Principles  
Security design principles are the foundational guidelines used to build secure computer 
systems,   networks,   applications,   and   cloud   environments.   These   principles   help 
organizations protect information assets from threats such as unauthorized access, data 
breaches, malware, insider attacks, and service disruptions. 
1. Introduction to Security Design Principles 
What are Security Design Principles? 
Security design principles are a set of best practices and guidelines that ensure a system 
is designed with security as a core requirement from the beginning of development, 
rather than adding security later. 
Why are they important? 
1. Protect sensitive data and resources. 
2. Reduce vulnerabilities and attack surfaces. 
3. Ensure reliable and continuous system operation. 
4. Support compliance with security standards and regulations. 
5. Build trust among users and organizations.

3. Major Security Design Principles 
3.1 Principle of Least Privilege 
Definition: 
Users, applications, and processes should be given only the minimum permissions 
necessary to perform their tasks. 
Explanation 
Limiting privileges reduces the risk of accidental or malicious misuse of resources. 
Example 
A student account can view course materials but cannot modify examination records. 
Benefits 
 Reduces attack impact. 
 Prevents unauthorized actions. 
 Improves accountability. 
This principle is widely implemented using Role-Based Access Control (RBAC). 
3.2 Defense in Depth 
Definition:

Access should be denied by default unless explicitly permitted. 
Explanation 
A secure system starts with no permissions and grants access only when authorized.

3.4 Economy of Mechanism (Simplicity) 
Definition: 
Security mechanisms should be simple, small, and easy to understand. 
Explanation 
Complex systems are harder to test, maintain, and secure. Simplicity reduces the 
chance of security flaws. 
Example 
A simple password policy is easier to enforce than a highly complicated authentication 
process. 
Benefits 
 Fewer vulnerabilities. 
 Easier maintenance and auditing. 
 Improved reliability. 
3.5 Complete Mediation 
Definition: 
Every access request to a resource must be checked for authorization. 
Explanation 
The system should not assume that a user who was previously authenticated is always 
authorized for future requests. 
Example 
Each time a user accesses a confidential file, the system verifies their permissions. 
Benefits 
 Prevents unauthorized access. 
 Ensures consistent enforcement of security policies. 
 Improves accountability.

Definition: 
Security should not depend on secrecy of the system design or implementation.

A system should remain secure even if its design is publicly known. Only secret keys or

3.7 Separation of Privilege 
Definition: 
Access to critical operations should require multiple conditions or approvals. 
Explanation 
No single user or process should have complete control over sensitive operations. 
Example 
A financial transaction above a certain amount requires approval from two managers. 
Benefits 
 Reduces insider threats. 
 Prevents abuse of power. 
 Improves accountability and oversight. 
3.8 Least Common Mechanism 
Definition: 
Minimize the sharing of resources among users and processes. 
Explanation 
Shared resources can become channels for information leakage or attacks.

Multicast Concepts 
Introduction 
Multicasting is a communication method in computer networks where a sender 
transmits data to a group of interested receivers simultaneously. Instead of sending 
separate copies to each receiver (unicast) or sending to all devices (broadcast), multicast 
sends data only to members of a multicast group. 
 
Types of Data Transmission 
1. Unicast 
 One sender → One receiver.

Sender ----> Receiver 
2. Broadcast 
 One sender → All devices in the network.  
 Example: ARP requests.

3. Multicast 
 One sender → Selected group of receivers.  
 Example: Live video streaming.  
            --> Receiver 1 
Sender ----> Receiver 2 
            --> Receiver 3 
 
Multicast Group 
A multicast group is a collection of devices interested in receiving the same data 
stream. 
Features 
 Devices can join or leave at any time.  
 Each group is identified by a multicast IP address.  
 Reduces network bandwidth usage.

 224.0.0.0 to 239.255.255.255  
 Class D IP addresses  
Examples: 
 224.0.0.1 → All hosts  
 224.0.0.2 → All routers

QoS (Quality of Service) Design 
Definition 
Quality of Service (QoS) is a network design technique used to manage and prioritize 
network traffic so that important applications receive the required bandwidth, low delay, 
low jitter, and minimal packet loss. 

CECS0004 – COURSE FOR DESIGN PROFFESSIONAL BE-VIII SEM 
Mr. ANUJESUS DHARMARAJ ME.,MSc.,BE.,BEd.,DSc.       ASST.LECTURER,SJUIT 
QoS ensures that critical services such as voice calls, video conferencing, and real-time 
applications perform efficiently even during network congestion. 
 
Objectives of QoS Design 
1. Prioritize important traffic.  
2. Reduce network congestion.  
3. Minimize packet loss.  
4. Control delay (latency).  
5. Reduce jitter (variation in packet arrival times).  
6. Improve overall network performance.  
 
Need for QoS 
Without QoS: 
 All packets are treated equally.  
 Voice and video traffic may suffer delays.  
 Network congestion can affect critical applications.  
With QoS: 
 Important traffic receives higher priority.  
 Better user experience.  
 Efficient utilization of bandwidth.  
 
QoS Parameters 
1. Bandwidth 
 Amount of data transmitted per second.  
 Measured in bps, Kbps, Mbps, or Gbps.  
Example: 
A video conferencing application may require 5 Mbps bandwidth. 
2. Delay (Latency) 
 Time taken for a packet to travel from source to destination.  
 Measured in milliseconds (ms).

Formula: 
Delay=Processing+Queuing+Transmission+Propagation 
3. Jitter 
 Variation in packet arrival times.  
 High jitter affects voice and video quality.  
Example: 
 Packet 1 arrives in 10 ms.  
 Packet 2 arrives in 30 ms.  
 Packet 3 arrives in 15 ms.  
This variation is called jitter. 
4. Packet Loss 
 Occurs when packets are dropped due to congestion or errors.  
Effects: 
 Poor audio quality.  
 Video interruptions.  
 Data retransmissions.

Cloud & Virtual Networks 
Introduction 
Cloud Networking refers to the use of network resources and services hosted in a cloud 
environment. It enables users to access applications, storage, and computing resources 
over the Internet. 
Virtual Networking is the creation of software-based networks that operate 
independently of the underlying physical network infrastructure. It allows devices, 
servers, and applications to communicate as if they were connected on the same 
physical network.
